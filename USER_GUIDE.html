Repo-aware AI Assistant

CodeMind

User Guide

Version 0.0.1-SNAPSHOT Audience Developers Scope CLI & Interactive Shell

CodeMind is a repo-aware AI assistant you run from your terminal. Point it at a codebase and it can answer questions about the code, explain end-to-end API flows, propose and apply refactors, and draft commit messages and changelogs — all grounded in the actual files it has indexed.

There are two ways to use CodeMind:

  • Subcommands — one-shot commands like codemind ask "..." or codemind commit. Best for scripting and quick tasks.
  • Interactive shell (REPL) — launch with no arguments and chat with the assistant. Best for exploring a repo.

1Quick start

# 1. Build
mvn clean package

# 2. Start the vector store + embeddings (Docker)
docker compose up -d chroma ollama ollama-pull

# 3a. Run a one-shot command
java -jar target/codemind.jar ask "what does the login flow do?"

# 3b. …or open the interactive shell
java -jar target/codemind.jar

On startup the interactive shell automatically indexes the directory you launched it from, so open your terminal in the repo (or parent workspace) you want analyzed before you run it.

No Docker?

Set CODEMIND_VECTOR_STORE=memory to use the in-process fallback store (hash-based embeddings — functional, lower recall, no Chroma/Ollama needed).

2Prerequisites

  • Java 21+
  • Maven (use your system mvn)
  • Docker for the Chroma vector store + Ollama embeddings — or CODEMIND_VECTOR_STORE=memory to skip it
  • API key for the chat model, exported as CODEMIND_AIHUB_KEY (falls back to the default key in application.yaml if unset)

3Commands

Run any of these as java -jar target/codemind.jar <command>, or type them at the shell prompt (without the java -jar … part).

CommandWhat it does
index [path]Index a repo for semantic search. Defaults to the current directory. Add --force to re-index unchanged files.
ask "<question>"Ask a natural-language question about the indexed code. Add --verbose to see the reasoning trace.
refactor <path>Analyse a file/folder for code smells and propose a phased refactor plan. Add --apply to apply Phase-1 safe extractions, --verbose for the full trace.
commitStage changes, draft a Conventional Commits message from the diff, and create the commit (after confirmation).
changelog [range]Draft a changelog from a git revision range (default HEAD~1..HEAD). Add --plain for a plain-English paragraph instead of the grouped list.

Two more commands exist but are hidden (advanced / not user-facing yet): do "<free-form request>" routes any request to the right specialist automatically, and rollback (placeholder) will restore files from a previous refactor --apply.

index

codemind index                       # index the current directory
codemind index "D:\workspace\bank-service"
codemind index --force .             # re-index everything, ignore the cache

For a fleet of microservices, index the parent workspace so cross-service questions work:

codemind index "D:\workspace\Central Services"

ask

codemind ask "list all REST endpoints grouped by module"
codemind ask "explain the customer onboarding flow end to end" --verbose

refactor

codemind refactor src/main/java/com/acme/OrderService.java          # analyse only
codemind refactor src/main/java/com/acme/OrderService.java --apply   # analyse, then apply Phase 1

--apply first prints the plan, then asks "Apply Phase-1 refactor to …?" before changing anything. Files are backed up before they're rewritten.

commit New behavior

commit now performs the whole flow end-to-end:

  1. If nothing is staged, it stages everything with git add -A. (If you've already pre-staged a partial change, it leaves your staging alone.)
  2. It reads the staged diff and drafts a Conventional Commits message (feat(cli): …, fix(agent): …, etc.).
  3. It shows you the message and asks "Apply this commit?"
  4. On confirmation it runs git commit -F with the drafted message.
codemind commit
Safe by default

If the working tree is clean (or you're not in a git repo), it prints "Nothing to commit" and stops. It also refuses to commit if the model returned an error instead of a real message.

changelog

codemind changelog                      # HEAD~1..HEAD, grouped by type
codemind changelog HEAD~5..HEAD         # last 5 commits
codemind changelog v1.2.0..HEAD --plain # plain-English paragraph

The default grouped output sorts changes into Features / Fixes / Refactors / Perf / Other based on Conventional-Commit types; --plain produces a narrative summary instead.

4Interactive shell (REPL)

Launch with no arguments:

java -jar target/codemind.jar

You'll get a prompt that shows the current mode:

  codemind  ask  >

Just type a question — you don't need to prefix it with ask:

  codemind  ask  >  where is the JWT token validated?

Modes

Changed

CodeMind now has one mode switch with two settings. This replaces the old two-axis ask|agentic + manual|auto system — there is no separate "execution mode" anymore.

ModeBehavior
ask (default)Q&A and analysis. Destructive actions (commit, refactor apply) ask for confirmation first.
agenticDeeper cross-file reasoning, and destructive actions auto-apply without prompting.

Switch between them:

  • /a or /mode — toggle ask ↔ agentic
  • /ask — force ask mode
  • /agentic — force agentic mode
  • Alt+A — keyboard toggle
  codemind  ask  >  /a
  mode: agentic
  codemind  agentic  >  explain the full payment flow across all services

Shell built-ins

InputAction
index [path]re-index (current dir by default)
commitdraft + apply a commit (asks first in ask mode, auto-applies in agentic)
changelog [range] [plain]draft a changelog
refactor <path>plan + apply a refactor (asks first in ask mode)
clearclear the screen, reset to ask mode, re-index the current directory
helplist commands
exit / quitclose CodeMind
!<command>run a raw shell command in the project directory (e.g. !git status)

Short, well-known shell commands (like git status, ls, docker ps) are detected and run directly even without the ! prefix. Anything that looks like a question is sent to the assistant instead.

Shell UX tips

  • Tab completes commands and modes.
  • Up / Down browse input history (persisted to ~/.codemind_history).
  • Ctrl+C cancels the in-flight operation and returns to the prompt.
IntelliJ note

If Up/Down doesn't work inside IntelliJ's plain Run console, enable terminal emulation for that run configuration, or run CodeMind from Windows Terminal / PowerShell. The plain console doesn't always forward arrow-key escape sequences.

5Models & vector store

CodeMind splits chat and embedding traffic across two backends:

  • Chat model — org OpenAI-compatible endpoint (qwen3.5-35b on https://ai-hub.f1arl.com). Your CODEMIND_AIHUB_KEY only permits this model.
  • Embeddings — Ollama in Docker. Default all-minilm (384-dim, fast). Swap to nomic-embed-text (768-dim, better recall) via OLLAMA_EMBED_MODEL=nomic-embed-text.
  • Vector store — Chroma in Docker.
Re-index required

If you change OLLAMA_EMBED_MODEL you must re-index — collections are pinned to the original embedding dimension. Delete <repo>/.codemind and the Chroma codemind collection, then index <path> again.

Configuration knobs

All optional — defaults match docker-compose.yml:

VariableDefaultPurpose
CODEMIND_AIHUB_KEY(yaml default)Chat model API key
CODEMIND_VECTOR_STOREchromamemory bypasses Chroma + Ollama
OLLAMA_EMBED_MODELall-minilmEmbedding model (re-index after changing)
OLLAMA_BASE_URLhttp://localhost:11434Ollama endpoint
CHROMA_HOST / CHROMA_PORThttp://localhost / 8000Chroma endpoint
CHROMA_COLLECTIONcodemindChroma collection name
CHROMA_TENANT / CHROMA_DATABASEdefault_tenant / default_databaseChroma namespace

Indexing tuning (in application.yaml):

  • codemind.embed.parallelism (default 4) — concurrent batches to Ollama.
  • codemind.embed.batch-size (default 16) — chunks per batch.
  • codemind.patterns.max-file-size-bytes (default 1,000,000) — skip large/generated files.
  • codemind.patterns.* — override language/framework classification keywords for your stack.

Local caches

<repo>/.codemind/chunks.bin   # Chroma mode: chunk text/metadata (vectors live in Chroma)
<repo>/.codemind/index.bin    # memory mode: chunks + local embedding vectors

The .codemind folder is self-git-ignored, so it won't pollute the repos you index.

6Troubleshooting

No useful answer

  • Make sure you indexed the right repo/workspace (index <path>).
  • For broad cross-file questions, switch to agentic mode.
  • Indexing failures now tell you whether the path is missing, not a directory, or unreadable.

Model call / config failures

  • Confirm CODEMIND_AIHUB_KEY is set in the same terminal.
  • Verify the endpoint URL and model name in application.yaml.

Chroma / vector store

  • Startup connection error → ensure docker compose up -d chroma is running and reachable at ${CHROMA_HOST}:${CHROMA_PORT}.
  • No results after a Docker volume wipe → re-run index <path> to repopulate the collection.
  • To skip Chroma entirely → restart with CODEMIND_VECTOR_STORE=memory.

Ollama / embeddings

  • connection refused to localhost:11434 → Ollama container isn't up. docker compose up -d ollama, then docker exec codemind-ollama ollama list to confirm.
  • model not found → the one-shot pull failed: docker exec codemind-ollama ollama pull all-minilm.
  • First index pass is slow → Ollama loads the model into memory on the first request; subsequent embeddings are fast.

commit did nothing

  • "Nothing to commit" means the working tree is clean or you're not in a git repo.
  • If it refused after drafting, the model returned an error string instead of a message — re-run, or check the staged diff is meaningful.

Confirmation prompts

  • Destructive actions prompt in ask mode and auto-apply in agentic mode. Switch with /a if you want the opposite behavior.
